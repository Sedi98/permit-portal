Executive Summary

Permit Portal enerji sahəsində icazə müraciətlərinin qəbulu və inzibati emalı üçün inkişaf etdirilən rəqəmsal platformadır. Mövcud repozitoriyada vətəndaş üçün Next.js portalı, əməkdaşlar üçün React/Vite operator paneli və ortaq xarici backend ilə işləyən API qatları mövcuddur. Vətəndaşın müraciət yaratması, sənəd təqdim etməsi, çatışmazlığı aradan qaldırması və nəticəni əldə etməsi üçün artıq funksional baza formalaşıb.

Təklif olunan modeldə myGov xidmətə giriş və vətəndaşla əlaqə kanalı, Permit Portal isə icazənin sahə qaydalarını və qurumdaxili icrasını idarə edən sistem olur. myGov ID ilə identifikasiya, razılaşdırılmış dövlət məlumatlarının sorğulanması, status və nəticənin myGov-a çatdırılması ayrı inteqrasiya müqavilələri kimi nəzərdən keçirilir.

Əsas qərar: bir icazə növü və məhdud məlumat dəsti ilə pilot başlatmaq; mövcud backend-i modul sərhədləri ilə genişləndirmək; ilkin mərhələdə ayrıca mikroservis platforması qurmamaq.

İlk mərhələdə təmin ediləcək nəticə

İstifadəçi myGov-dan xidmətə keçir, kimliyini təsdiqləyir, tələb olunan məlumatların məqsədini görür, müvafiq razılığı verir və əvvəlcədən doldurulmuş ərizəni yoxlayır. Müraciət qeydiyyata alınır, mövcud operator iş axını ilə emal edilir, istifadəçiyə status və yekun sənəd təqdim olunur. Ödəniş və imza yalnız provayder tərəfindən təsdiqlənmiş nəticələr əsasında tamamlanır.

F01 · Təhlükəsiz myGov ID girişi P0

Məqsəd və üstünlük: əlavə parol yaratmadan etibarlı kimlik təsdiqi və yarımçıq müraciətə təhlükəsiz qayıdış.

myGov əlaqəsi: myGov ID identifikasiya provayderi kimi istifadə olunur; xidmət kataloqunda yerləşmə ayrıca razılaşdırılır [R1].

İş prinsipi və backend: BFF birdəfəlik giriş tranzaksiyası yaradır, state və dəstəklənən protokola uyğun PKCE/nonce bağlayır. Callback kodu serverdə dəyişdirilir; issuer və subject əsasında daxili hesab uyğunlaşdırılır. Brauzerə provayder tokeni deyil, HttpOnly sessiya cookie-si verilir.

İstifadəçi flow-u: xidmət seçimi → giriş → provayderdə təsdiq → təhlükəsiz geri dönüş → şəxsi kabinet. İmtina zamanı qaralama itmir, yenidən giriş təklif olunur.

API və inteqrasiyalar: mövcud layihə çağırışı GET /api/auth/mygov/redirect-url; hədəf üçün nümunə /api/v1/auth/start və /auth/callback. Dəqiq OIDC imkanları provayder müqaviləsi ilə yoxlanır.

Təhlükəsizlik: icazəli redirect siyahısı, login CSRF müdafiəsi, sessiya rotasiyası, logout/revocation, MFA səviyyəsinin riskə uyğun yoxlanması. FİN URL və analitika hadisələrinə yazılmır.

F02 · Məqsəd üzrə razılıq mərkəzi P0

Məqsəd və üstünlük: vətəndaş hansı qurumun hansı məlumatı nə üçün və nə vaxta qədər işlədəcəyini görür, seçimlərini idarə edir.

myGov əlaqəsi: myGov-un mövcud razılıq idarəetmə təcrübəsi nəzərə alınır [R3–R4]; layihə üçün ümumi razılıq API-si təsdiqlənmiş fakt kimi qəbul edilmir.

İş prinsipi və backend: xidmət üzrə məlumat manifesti göstərilir. Server dəyişməz razılıq versiyası, mətnin hash-i, sahələr, alıcı, məqsəd və müddəti saxlayır. Hər reyestr çağırışında aktual razılıq və hüquqi əsas yenidən yoxlanır.

İstifadəçi flow-u: məlumat tələbi → izah → ayrı seçimlər → təsdiq/imtina → qəbz → tarixçə və ləğv. Məcburi məlumatın verilməməsinin xidmətə təsiri aydın göstərilir.

API və inteqrasiyalar: nümunə POST /api/v1/consent-requests, POST /consents, POST /consents/{id}/revoke; razılaşdırılarsa xarici razılıq adapteri.

Təhlükəsizlik: hazır seçilmiş checkbox yoxdur; gizli ümumi razılıq yoxdur; ləğv keşə və növbədəki işlərə ötürülür. Qanuni saxlanma öhdəliyi razılıq ləğvi ilə avtomatik yox olmur.

F03 · Avtomatik doldurma və mənbə təsdiqi P0

Məqsəd və üstünlük: şəxsiyyət və əlaqəli reyestr məlumatlarının təkrar yazılmasını azaltmaq; vətəndaşa hər sahənin mənbəsini göstərmək.

myGov əlaqəsi: kimlik myGov ID ilə bağlanır, əlavə dövlət məlumatları yalnız razılaşdırılmış mübadilə kanalı ilə alınır. myGov interfeysində məlumatın görünməsi layihəyə avtomatik çıxış vermir.

İş prinsipi və backend: minimal məlumat dəsti sorğulanır, cavab sxemi yoxlanır, source, verified_at, expires_at və evidence_id saxlanır. İstifadəçinin yazdığı sahə ilə təsdiqlənmiş sahə fərqləndirilir; etibarlılıq müddəti bitmiş məlumat submit-dən əvvəl yenilənir.

İstifadəçi flow-u: razılıq → məlumatların alınması → doldurulmuş formanın baxışı → fərqin bildirilməsi → təsdiq. Mənbədə səhv varsa düzəliş müraciətinin ünvanı göstərilir.

API və inteqrasiyalar: nümunə POST /api/v1/profile-resolutions; şəxsiyyət reyestri və xidmət tələb edərsə vergi/əmlak adapteri. Məlumat sahibi, sahələr və səlahiyyət ayrıca razılaşdırılır.

Təhlükəsizlik: yalnız tələb edilən sahələr; istifadəçi və məqsəd üzrə keş; başqa vətəndaşın FİN-i ilə sorğu qadağası. Mənbə xətası hüquqi uyğunsuzluq kimi təqdim edilmir.

F04 · Rəqəmsal ərizə və bərpa edilən qaralama P0

Məqsəd və üstünlük: istifadəçinin müraciəti mərhələlərlə tamamlaması və cihaz/sessiya dəyişdikdə təhlükəsiz davam etməsi.

myGov əlaqəsi: razılaşdırılmış xidmət keçidi konkret icazə növünü açır; myGov-da görünən müraciət identifikatoru daxili nömrə ilə uyğunlaşdırılır.

İş prinsipi və backend: mövcud draft/submit prosesi genişləndirilir. Forma sxemi versiyalanır, server məcburi sahələri və sənədləri yoxlayır, submit idempotency açarı ilə bir dəfə icra olunur. Qeydiyyat və hadisə eyni tranzaksiyada yazılır.
